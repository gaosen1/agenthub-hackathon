# AgentHub 录屏演示拍摄脚本

> 目标时长 3'30" 左右（可剪到 90s 短片版）。核心叙事：**本地会话一推上云 → agent 无人值守干活 → 钉钉交付 → 拉回本地无缝续写**。
> 演示仓库：`sci-calculator`（Web 科学计算器，React + Vite；已清理探针痕迹、重建可信历史）。

## 一、产品一句话（开场定调）

AgentHub 是本地 Coding Agent 会话的**云端接力平台**：把本地改到一半的上下文一条命令移交云端沙箱，agent 夜间无人值守执行，钉钉群实时交付，成果拉回本地 git 合并、会话续聊。

要传递的三个记忆点：
1. **一条命令接力**：`ah push --task --bot`，本地 repo + session 全量上云
2. **全程可见可干预**：Web 控制台流式看 agent 干活，钉钉群追问即续跑
3. **成果无损回流**：`ah pull` git 合并 + 会话时间线合并，本地接着聊

## 二、录制前准备清单（开拍前逐项打勾）

### 环境
- [ ] hub 已启动且**录制期间不碰代码**（tsx watch 重启会造成接口空窗）
- [ ] Web 端清掉历史 handoff（列表干净，只留演示用的 1 个任务）
- [ ] Aone 远端无残留沙箱（`listSandboxInfos` 应为 0，或提前预热一个）
- [ ] 沙箱镜像为最新版（含 code-server、无人值守约束）
- [ ] 钉钉机器人 IP 白名单、凭证有效；测试群干净、无关群免打扰

### 演示任务选择（关键）
- [ ] 选 **1~3 分钟能跑完、diff 可视化**的小任务，例如：
  - 「给 README 顶部加一个快速链接区，指向 功能特性 / 使用方法 / 常见问题」
  - 「给 X 模块补一个 utils 函数 + 单元测试」
- [ ] 指令明确无歧义（避免模型反问；无人值守约束虽已兜底，但任务本身要干净）
- [ ] **正式录制前完整预跑一遍**，确认时长、产出、无报错

### 画面
- [ ] 分辨率 1080p+，OBS 双轨（屏幕 + 麦克风）
- [ ] 终端换深色主题 + 等宽字体，字号 ≥14px，与 Web 的终端工业风呼应
- [ ] 布局：终端与浏览器各占半屏（Act 1/4 用终端全屏，Act 2/3 切浏览器/钉钉）
- [ ] 关闭所有通知弹窗（系统勿扰模式）

### 兜底策略
- [ ] 每个实拍环节**先完整录一遍备份**；正式剪辑时逐段取成功版本
- [ ] 沙箱冷启动约 30~60s：要么提前预热，要么剪辑加速 + 字幕「沙箱按需唤醒中」

## 四、防翻车备忘（血泪教训版）

1. **录制期间绝对不改 hub-server 代码**——watch 重启会让前端轮询成片报错
2. push 后沙箱冷启动有窗口期，**等 status 变 running 再切 Web 画面**
3. 演示任务避免「帮我选 A 还是 B」类模糊指令（无人值守约束会强制模型自主决策，但可能产生你不想要的方向）
4. 钉钉消息到达有延迟，旁白节奏预留气口
5. 24h 长任务能力是**口播点**不是实拍点（「夜间无人值守任务活跃即续命，永不撞墙钟」一句话带过）
6. 若现场某环节失败：切备份素材，不要现场调试（调试画面一帧都不要留）

## 五、实录剧本（sci-calculator · 百分比 bug 修复）

> 用真实仓库 + 真实 bug 演绎「移交」：本地聊出问题和方案 → 一句指令移交云端 → 云端带着完整上下文继续干完。
> 仓库里的 bug 是真的：`App.jsx` 把 `%` 一律替换成 `/100`，导致 `100+10%` 算出 **100.1**（真实计算器应为 110）。
> 预计云端执行 2~4 分钟，适合实拍节奏。

### 第 1 轮（本地，建上下文）
```
看下这个计算器项目，现在有哪些功能？表达式是怎么求值的？
```
预期：agent 读代码，概述功能 + 指出 `calculateResult` 用字符串替换 + `new Function` 求值。（镜头：本地终端流式输出，建立「本地协作」的第一印象）

### 第 2 轮（本地，发现真 bug）
先切浏览器 `npm run dev` 演示输入 `100+10%` 得到 100.1，然后回终端：
```
我输入 100+10% 得到的是 100.1，但计算器语义应该是 110（即 100 的 110%）。这是不是 bug？原因在哪？
```
预期：agent 定位到 `%` 被无脑替换为 `/100`，与运算上下文无关；给出修复思路（`x+y%` → `x*(1+y/100)`，独立 `x%` 保持 `x/100`）。

### 第 3 轮（本地，定方案——为移交铺垫）
```
方案可以。另外求值逻辑现在写在组件里，顺便把它抽到 utils，加上 vitest 单测。
```
预期：agent 给出实施清单（可打断，不用等它说完）。此时旁白点题：**「方案定了，但实现 + 测试还要跑一会儿——我马上有个会。以前只能占着本机等，现在直接移交。」**

### 移交（核心镜头）
```
ah push --task "按刚才讨论的方案修复百分比语义，把求值逻辑抽到 utils 并补 vitest 单测，完成并验证通过后 commit" --bot
```
旁白：**「注意 task 里没有重复方案细节——刚才两轮对话的上下文会随 session 一起移交，云端从我们停下的地方继续。」**（这是与「重新派一个新任务」的本质区别，字幕可强调）

### 后续（接回分镜脚本 Act 2~5）
- Web 控制台看流式执行（云端会先装 vitest，正好展示真实工作环境）
- 钉钉收到「✅ 云端任务完成 · 新增 N 个 commits」
- 本地 `ah pull` → `git log` 看云端 commit → `pnpm test` 当镜跑绿（强收尾）
- （可选）`npm run dev` 再输一次 `100+10%` = 110，前后呼应

### 预演检查点（开拍前必过一遍）
- [ ] 本地把第 1~3 轮完整聊一遍，确认 agent 能自己定位到 `%` 替换逻辑（不能靠提示词硬喂）
- [ ] 完整预演一次 push：确认云端任务 5 分钟内完成、不反问、commit 正常、pull 无冲突、`pnpm test` 通过
- [ ] 若预演中云端反问/跑偏：收紧 task 描述（把方案要点写全），但不要写全到失去「上下文移交」的叙事价值——保留「按刚才讨论的方案」这句，其余细节可适度补进 task
